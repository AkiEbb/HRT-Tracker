## v0.1 「能算」— 本地单机可用

**目标**：不登录也能记录、看曲线、导入导出。这一阶段验证的是**数据模型与 PK 引擎**，不是后端。

| #   | 交付                                                                    | 验收                                                           |
| --- | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| 1   | bun workspaces 骨架 + Biome + tsconfig + CLI 脚本                       | `bun run lint` / `bun test` 在空测试上绿                       |
| 2   | `packages/protocol`：内部 schema、`doseMG`/`doseEquivMG` 双字段、规范化 | 往返夹具：`doseMG` 逐条等值（§8.4-1）                          |
| 3   | `packages/pk-core`：catalog.json + `builtin` 引擎 + Worker 协议         | 对 Kira 夹具同输入同曲线，**容差 1e-6**                        |
| 4   | `packages/pk-core`：`transmtf` 引擎 + 引擎切换                          | 两引擎在同一记录上产生不同曲线（差异被断言，不是"大概不一样"） |
| 5   | `apps/web`：记录增删改查（本地 IndexedDB 或 OPFS）                      | 关浏览器重开数据在                                             |
| 6   | 图表：uPlot + 时间轴缩放 + **双模型叠加对比**                           | 1 万点滚动不掉帧（低端安卓实测）                               |
| 7   | 导入：Transmtf + Kira 备份；导出：`kira-hrt`                            | 夹具全绿；跳过项进报告                                         |
| 8   | `deploy/`：Workers 与 VPS 的构建产物都能起                              | 两条 CI 绿（此时还没有账号系统）                               |

**不做**：账号、同步、分享、通知、i18n（除框架接入）、OCR（已永久砍掉）。

**风险闸门**：第 1–2 天若 workspace TS 包在 Nitro 里打包失败，立即启用 §3 退路（挪进 `shared/`），**不纠缠**。

## v0.2 「能存」— 账号 + 同步

**目标**：打通 `注册 → 加锁 → 多设备同步` 的完整闭环。这是全项目风险最高的一段。

| #   | 交付                                                                 | 验收                                                   |
| --- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| 1   | `packages/crypto`：Argon2id、KEK/DEK 包裹、恢复短语、记录信封（AAD） | 单元测试覆盖：错密码、篡改密文、跨记录挪用密文全部失败 |
| 2   | Drizzle schema + 两套迁移（sqlite/pg）+ D1 迁移脚本                  | 同一份导出数据能写进三者之一并读回                     |
| 3   | 认证：邮箱口令 + TOTP + 注册邀请码开关                               | 注册流程五步顺序不可跳过（§6.3）                       |
| 4   | 会话（D1）+ 设备列表 + 即时撤销                                      | 撤销后同一 token 立刻 401                              |
| 5   | 同步：`GET /api/sync` 复合游标 + `POST /api/sync` CAS                | 1000 条落在同一时间戳时无整页跳过（§7.1）              |
| 6   | 冲突：`contentFingerprint` 共用 + 3 轮重试 + 人工确认列表            | 两端交替编辑 20 轮后收敛（不 ping-pong）               |
| 7   | 账号删除：硬删密文 + 撤销全部 session + 级联删分享                   | 删除后任何接口都拿不到该用户的任何字节                 |
| 8   | 加密备份导出 / 导入（换设备）                                        | 新设备只凭安全密码或恢复短语可恢复                     |

**不做**：分享、通知、OIDC、Passkey、校准。

**风险闸门**：若 D1 的 batch/参数限制迫使我们改协议，**改协议而不是改语义**（CAS 与幂等不可退让）。

## v1.0 「能对话」— MCP + 推送 + 剩余登录方式
